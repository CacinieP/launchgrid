# 技术取舍

[文档目录](README.md) · [架构](architecture.md) · [开发与调试](development.md)

以下记录当前源码已经采用的方案及代价，供后续变更讨论使用；不是未经验证的性能或产品留存结论。

## 原生界面与系统框架，无第三方 package

**选择**：一个 Swift Package，SwiftUI 内容结合 AppKit 外壳，使用系统 Combine、Carbon、CryptoKit、ServiceManagement 等能力。

**目的**：直接使用 macOS 的菜单栏、应用图标、窗口行为、权限和签名机制，保持依赖与分发链简单。

**代价**：平台限定为 Mac，需要维护 AppKit/SwiftUI 的焦点、sheet 和窗口生命周期；系统命令输出与 SDK 差异仍要做防御。无第三方依赖本身不代表体积、能耗或速度已经优于竞品。

## Carbon 注册全局热键

**选择**：默认围绕 F4 的五组热键，可在设置录制；先验证格式和 App 内重复，再尝试系统注册，失败保留原设置。录制期间临时释放 App 自己的热键。

**目的**：启动入口不要求用户先授予辅助功能权限；默认修饰组合集中、易记，避免大量普通字符键被全局吞掉。

**代价**：Carbon 是较老的接口；系统媒体键行为、系统保留键和其他 App 注册会影响可用性，不能承诺任意组合都可用。普通键要求 ⌘/⌥/⌃ 修饰，用户仍需通过冲突提示选择适合自己的组合。

## 单层布局与只读旧 Launchpad 导入

**选择**：versioned JSON 存根层顺序、单层文件夹和别名；与已安装 App 清单同步。旧布局用系统 sqlite3 只读解析 `items/apps/groups`，优先 bundle ID、唯一名称回退，只匹配安装清单。

**目的**：布局可备份、可校验，导入不碰系统库；没有旧库时给出可解释的失败，避免制造或修改系统状态。JSON 导入有 5 MB 限制，旧库子进程有大小/输出/超时边界。

**代价**：不支持任意嵌套文件夹或其他启动器的私有格式；数据库已删除就无法恢复旧顺序；跨机器路径变化、同名/重复 bundle ID 仍有匹配局限。损坏布局保留隔离文件，无法隔离时停止保存，需要用户处理原文件。

## 用包路径与父子 PID 关联单个应用

**选择**：从应用包路径内的可执行进程开始，递归纳入后代；用 PID 筛选 nettop/lsof 数据，不按被截断的进程名归属。

**目的**：避免名称相似或截断造成跨应用混入，也能包含包内 helper 和其外部子进程。

**代价**：托管系统服务、重归属进程、瞬间退出/新建 PID 不一定完整归入；CPU/网络快照并非同一原子瞬间。详情是系统可见范围内的排查工具，不是完整审计追踪。CPU 仍为 `ps` 平均值，内存累加也不是精确物理独占内存。

## 按需采样与系统工具

**选择**：进程约 2 秒刷新；网络可见时约 2 秒实时刷新、5 秒写增量历史。界面隐藏或模块关闭停定时器、丢弃旧 generation，重开重建基线。网络速率走接口计数器差分，进程流量走 nettop，连接走 lsof。

**目的**：让日常启动器后台不持续执行进程/网络采样；使用系统可提供的观测信息，首次无基线返回 0，避免把开机累计当速率。

**代价**：隐藏时段不计入累计，因此日/周/月不是全天账单；初次显示需等待采样，命令失败/权限可能使数据不完整。系统命令格式、默认接口变化与并发任务需要维护。当前不启用 App Sandbox，网络修复还会经过受约束的提权 shell/AppleScript 通路。

## 剪贴板 opt-in 与本机明文历史

**选择**：新安装默认关闭；旧版已有历史仅首次迁移延续原行为并说明。只收新纯文本，允许暂停、来源排除并清除旧匹配记录、确认清空；恢复不补录。JSON 文件权限 0600，7 天/200 条/256 KiB 单条限制，串行原子保存。

**目的**：让用户先决定是否后台收集；保留简单、透明的本机功能和旧版使用连续性；串行写避免较早快照覆盖删除结果。

**代价**：未做应用层加密，能访问该用户文件的进程仍可能读到内容；来源只是前台 App 估计，敏感标记也依赖来源 App，不能提供秘密识别保证。关闭不等于删除，过期清理按运行/使用触发，没有单独常驻擦除服务。

## 原生校验下载与显式安装

**选择**：默认每日可关闭地查询 GitHub 正式版，安装另需用户点击；资产 URL、SHA-256、bundle ID/版本、Developer ID Team 与 Gatekeeper 校验后，ditto 暂存、再验签、Foundation 替换。

**目的**：在无第三方更新框架下提供可检查的来源链；只替换可写 Applications 中的安装，失败有手动发布页入口。

**代价**：需自行维护下载、挂载、签名策略和重启流程；缺少 GitHub digest 的资产不能自动安装，Team 更换需调整策略；不支持提权更新不可写目录，也没有新版启动失败自动回滚。摘要不能单独证明发行者身份，签名/系统校验是并列要求。

## Developer ID、双阶段公证与对应源码

**选择**：开发包默认 ad-hoc；分发包用 Developer ID 和 hardened runtime。先公证/staple App，再装入 DMG 并独立公证/staple DMG；发行脚本默认检查源码 commit/版本、现有 release 与产物冲突。

**目的**：让从 DMG 拖出的 App 自带票据，使 Gatekeeper 校验针对实际分发内容；App 内源码链接和 Release 源码包指向确切构建 commit。用 `PUBLISH=0` 先形成可验收产物，再发布同一批文件。

**代价**：依赖 Apple 开发者身份、钥匙串凭据和在线公证服务；通用构建两套架构都要验证；ad-hoc 重建的代码身份变化可能使辅助功能授权失效。公证不替代功能验证，公开签名也不等同于无漏洞。

## AGPL-3.0-only

**选择**：根据项目所有者的明确决定，自 0.4.2 起采用 AGPL-3.0-only。保留完整 LICENSE，在 App 中携带许可证/源码 commit 链接，并在 Release 提供该 commit 的源码归档。

**目的**：清楚表达本版本的开源许可和对应源码获取方式，不用模糊的“开源”标签代替实际条文。

**代价与范围**：后续贡献、修改和分发需核对 [完整许可](../LICENSE) 的适用要求；本文不重写许可证或替代个案判断。历史 tag/commit 的许可记录保留，不把本次变更描述成自动改写所有历史版本。
